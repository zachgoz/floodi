# Flood forecasting implementation

## Primary forecast selection

The linked water-level and residual charts, upcoming event cards, future readouts and map simulation use one selected total-water forecast. Actual gauge measurements and the near-live NOAA display estimate are unchanged.

1. Prefer the historically screened **weather-response** forecast, up to 24h from the genuine measurement time.
2. If weather is missing or outside its learned range, use the separately screened **residual-response** forecast, up to 6h. It learns measured residual changes and tide-phase behavior, without meteorological extrapolation.
3. Preserve that native prefix exactly, then extend across **every available NOAA tide timestamp**. The recent departure fades over 48 hours toward a historical tide-level/phase pattern. A separately screened sustained-wind, pressure and rainfall response contributes while compatible forecast weather exists; it fades during the last 24 hours of that weather coverage. Later timestamps use the historical baseline with increasing uncertainty.
4. The far historical baseline is explicitly distinguished from a predictor that passed the improvement screen: its 14-day error was worse than persistence. It supplies a transparent outlook, not a claim of uniformly improved or operational accuracy. Insufficient history or incompatible references withhold that tail and retain the older screened 72h extension when supported.
5. If neither near-term model is supported, retain the existing steady projection; use tide only when no residual projection exists. Manual adjustments retain the user's override.

No silent steady tail is appended to a learned forecast. The new `tail` metadata records the historical baseline, separate historical/weather skill flags, actual weather support, training coverage and held-out errors. The older `extension` format remains readable for cached 72h issues. Cards disclose the selected horizon. Forecasts carry **limited confidence**, not an Experimental GUI label or an unsupported operational reliability claim. Historical error bounds can show **Flooding possible** even when the central forecast remains below flood stage. Water-level line colors indicate threshold exceedances; chart backgrounds stay neutral.

See [recorded-data proof, replay results and calibration limits](SURGE_ANALYSIS.md), the [full-range report](full-horizon-validation-2026-10-11.json), the [near-term numerical report](forecast-validation-2026-10-10.json), and the earlier [three-day report](three-day-validation-2026-10-11.json).

## Data and calculations

FIMAN gauge **30046** is retrieved through the Sunny Day Flooding platform. The platform's separate raw SUNNYD_CB_03 sensor is not interchangeable. NOAA astronomical prediction is station **8658163**, in feet MLLW. Gauge NAVD88 uses the existing +2.75 ft conversion and NOAA tide uses the existing +60 minute local phase. Neither adjustment has been independently surveyed/calibrated here. All calculations retain UTC; resident dates use America/New_York with DST.

`weatherResponse.ts` fits lead-specific residual-change ridge regressions with fixed penalty 20, purged chronological 70/30 evaluation and same-pair short-range ablation. Full-weather inputs are mph, wind-from degrees, inches and MSL hPa. `sources.ts` verifies returned unit metadata and UTC before parsing. Missing rain remains missing. Domain guards withhold extreme extrapolation rather than clip weather to a plausible-looking forecast.

`historicalOutlook.ts` fits an interpretable tide-level and one-hour tide-slope residual baseline, plus a separate weather regression using preceding 6h/24h north/east wind components, MSL pressure and its change, and 6h/24h rain totals. Penalty 20, 48h anomaly decay and 12h weather transition are declared before scoring and are not tuned to force a passing result. Each future tide timestamp evaluates its own pattern, so the long residual line follows tide-phase behavior rather than remaining flat. This is conditional history from the observed season; it does not invent annual climatology or add moon effects already in the tide.

Chronological issue-anchored evaluation through 336h uses realized reanalysis weather, excluding issued-weather error. Historical-only residual MAE at 5/7/14 days is approximately 0.435/0.463/0.610 ft versus steady 0.609/0.604/0.580 ft. The fixed historical improvement gate therefore **fails** at 14 days. The weather candidate improves same-pair historical errors, at approximately 0.307/0.320/0.369 ft, and passes its separate screen. The historical fallback is explicitly a baseline rather than a falsely promoted successful model. Error envelopes never narrow, and beyond 336h their square-root growth is a conservative assumption rather than measured interval coverage.

The older `weatherResponse.ts` eight-feature 48/72h extension remains a compatibility fallback. Its original point-error improvements and later event misses are retained in the three-day report. Neither those results nor the new point-error screen establishes improved storm detection or validated probabilities. Exact joined-prefix peak, onset, duration and event replay results must be read separately from the new issue-anchored point comparisons.

Nominal half-hour gauge sampling permits explicitly declared 10 second timestamp jitter. Longer observation outages remain gaps. Peak scoring preserves all native observed totals and a 6 minute grid. Provider non-evaluated spikes are not silently removed. Future/estimated observations never enter training or current measured trends.

`gaugePipeline.ts` projects from the genuine measurement timestamp and nowcasts reporting delay using the selected predictor. Measurements older than 1 hour cannot generate new numerical curves. `observationAt`, `forecastOriginAt` and `generatedAt` are separate. Total water = astronomical tide + forecast residual at identical UTC. The client retains server physical totals and re-expresses only the residual against its local tide; it never adds the previous residual twice.

Event crossings use the selected total series and user threshold. Threshold exceedances change the water-level line color; neither chart shades flooding periods. Peaks, open-ended/ongoing events, midnight/DST formatting and street proxy calculations share tested helpers. Max Street Flooding* is inches above threshold until a compatible validated street elevation is configured; the info control states that actual depth varies by street.

Selection retains the immediately preceding native forecast sample between updates, so ongoing floods cover the current time. Outlook risk excludes events whose actual threshold crossing has already ended. Error bounds stop at the same supported timestamps as the central forecast. Readouts and the map do not carry the last learned value beyond its forecast horizon; they use explicitly labeled astronomical tide or display unavailable. Estimated and simulated map levels carry their actual source label.

## Scheduling and caching

- `refreshResidualHistory`: daily refresh of 90 days of public history, ending 7 days back for archive availability. Saves immutable history in private Storage, fits once, and saves a versioned immutable private model plus current pointer. Current model version: `gauge-weather-response-v6`. Older caches are rejected and need regeneration.
- `generateFloodOutlook`: every 10 minutes, maximum one instance. Loads validated daily model, retrieves recent real gauge/tide/issued weather, projects without refitting and saves the cached public result. Missing, stale or incompatible model/data produce an unavailable result and client fallback.
- Retrieval includes 21 future days of NOAA tides and up to 16 calendar days of forecast weather. The native six-minute near-term prefix is unchanged; the longer public tail samples tides at 15-minute intervals, including the source endpoint. Crossings therefore use the same continuous total series throughout. Public cached payloads are bounded at 5,000 points; the private full-resolution issue snapshot is bounded at 512 KB. Weather failures preserve the supported measured prefix and the explicitly declared historical baseline.
- If panning loads NOAA tides beyond the server's endpoint, the client appends the same shared historical projector from a validated public tide-pattern summary. It preserves every available physical server total and does not fetch weather, refit a model, call Gemini or use browser credentials. That browser extension has no fixed day limit; it stops at the actual loaded tide endpoint. Cached server issues are bounded to 32 days for size validation.
- Every issue stores an immutable private snapshot of exact measured water, residual, tide, issued weather, fitted model, UTC times and reference metadata. Input payload is bounded at 512 KB; no final historical forecast snapshot can overwrite an earlier issue.
- Gemini attempts are transactionally capped at once/hour, including failures. Other updates use current calculated evidence. Provider or reservation failures retain the numerical forecast.
- `GET /api/outlook` and the dashboard are cached reads; visitors cannot trigger training or Gemini. Results expire after 2 hours. The client polls every 10 minutes and rejects invalid, expired, reference-incompatible or unsupported results.

Private paths include `forecast_models`, `forecast_model_archive`, `forecast_input_archive`, `forecast_explanation_state`, `forecast_training` and `forecast_archive`. Existing rules deny client access outside public location data. Model caches verify version, phase, vertical offset, gauge, units, datum, date chronology/age, coefficients, feature bounds and validation gates.

## Gemini and credentials

Vertex uses **gemini-3.8-flash**, server-side Google Auth Library Application Default Credentials. `VERTEX_AI_PROJECT` selects the existing Vertex-enabled project independently of Firebase storage/deployment; otherwise the ADC project is used. The supplied local service account was previously verified against its existing Vertex project. Earlier 403 responses came from targeting the Firebase project with Vertex disabled, not proof that the credentials were invalid.

Gemini receives calculated values, thresholds, evidence, confidence, per-lead validation and labeled baseline/learned components. At most 80 original forecast points are sampled for its input, retaining endpoints and total-water extrema; forecasting and event calculations retain the complete series. It returns structured JSON selecting a headline and at most four supplied evidence IDs. Schema and risk checks reject invented evidence or unsupported risk headlines. Numerical prediction stays outside Gemini. Errors use the calculated summary.

Production needs the Firebase runtime identity's existing Firestore/Storage permissions and Vertex invocation permission in the selected existing Vertex project. Cross-project production invocation has not been verified. Prefer workload identity/runtime ADC; never deploy a local private-key file. For local scripts, ignored `functions/.env.local` can select `../service-account.json` and the existing Vertex project. Do not put private credentials or ADC variables in `VITE_` variables. Environment/service-account files and evaluation artifacts are ignored; the previously tracked app `.env` is removed from the index.

Deploy Functions, Hosting rewrite and rules in the existing Firebase project after reviewing firebase.json/Codemagic configuration. Run the daily history/model job successfully before numerical inference. These changes and the preview are local; production has not been redeployed.

## Mobile interface and verification

Next Flooding Events is first. Separate tide and residual plots share one card, one toolbar and synchronized pan/zoom. Return to Live recenters the existing viewport; only explicit default reset resets zoom. Compact legends and a limited-confidence badge replace long annotations; detailed evidence and calibration remain behind info/expanders. The water-level chart shows the FloodCast water-level series and NOAA astronomical prediction without extra uncertainty or comparison curves or flood background shading. Historical error bounds still inform possible-flood status and model details. The optional steady comparison is confined to the surge chart and does not change hazard calculations.

The shared **3d** and **7d** buttons show the next three/seven future days on both charts while retaining the configured position of the live line. **All** shows the actual loaded NOAA endpoint. The 12h/24h/48h buttons describe total viewport width. Fetching more buffered data does not automatically expand the viewport; the user explicitly selects All again to see a newly loaded endpoint. Zooming, touch pan/pinch and Return to Live preserve long-range views and the user's chosen duration. Next Flooding Events considers the complete selected range, showing two cards initially and at most five upcoming events.

Weather defaults to a compact overview on the water chart's time scale. **Hourly** opens a scrollable wind/direction and rainfall strip for that same range, using actual hourly records and showing missing values as unavailable. Browsing detailed weather preserves the chart zoom and the inspected hour during live updates. **Add Comment** sits below the plot, clear of the wind and rain rows; the chart's N shortcut retains the same current chart-time selection.

During `npm run dev`, a Vite server scheduler refreshes `functions/evaluation/outlook.json` at startup and every 10 minutes. It compiles Functions once and runs `preview_residual.js --reuse-model`, retrieving actual gauge observations, NOAA tides and forecast weather. The private daily model cache is reused only when its archive bytes/path, physical reference, fit dates and validation gates match. HTTP reads still only return the public cache; opening the dashboard cannot start inference, training or Gemini. Evaluation archives and private model/input caches are denied by Vite's file server.

Archive discovery continues the previous local preview's archive, or uses `FLOODI_FORECAST_HISTORY` when explicitly configured. On the first run it discovers a collected `regional-gauge-history-YYYY-MM-DD-90d.json` under `functions/evaluation/`. A fit whose latest training observation is over 14 days old still requires recollecting historical data. Failed inference retains the prior artifact's original expiry and retries with backoff; hanging processes are terminated after 5 minutes. No stale forecast is given a new timestamp.

Dashboard cache reads recover on focus, reconnect, visibility return, pull-to-refresh and successful local inference. Failed reads retry after 30 seconds and retain a still-valid previous issue; expired forecasts are removed immediately. Forecast freshness uses the real clock separately from the chart's rounded, five-minute viewport clock. The steady projection remains a fallback when no current compatible evaluated forecast can be read.
