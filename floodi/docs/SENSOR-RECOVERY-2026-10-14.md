# Sensor archive and surge recovery

The public October observation bucket stopped at `2026-10-12T00:57:05Z` (October 11, 8:57 PM EDT), although gauge 30046 continued reporting through the Sunny Day Flooding provider and production proxy. Live Google Cloud logs confirmed repeated Firestore rejection of an undefined NWS precipitation field. Earlier failures also reported expired transactions. The current numerical forecast service was healthy; the local preview cache had expired.

Weather ETL now omits absent/invalid measurements, retains genuine zeros, and bounds requests. Observations, predictions and backfill isolate source failures and use sanitized atomic nested-field merges without reading or rewriting monthly buckets. Empty records cannot erase archived weather. Recovery upserts preserve saved event images and metadata and do not delete monthly history. The recovery endpoint accepts `days=1..60`, defaulting to the existing 60-day range.

The dashboard independently checks each observation source and can retrieve current same-gauge FiMAN measurements even when the stored bucket is stale or NOAA is fresh. It preserves station/datum provenance and the existing one-hour freshness gate. FiMAN parsing matches the requested platform, tolerates qualified or malformed camera timestamps, and merges validated same-gauge samples across platform responses. The local preview was refreshed from current public observations, NOAA tides and weather without invoking Gemini.

The final interaction run exposed an existing race when Return to Live followed a surge pan before the tide chart's delayed notification. Genuine external viewport commands now invalidate stale notification deduplication, keeping both plots aligned without resetting zoom.

Verification: **583 app tests and 46 backend tests passed**, both builds passed, and ESLint reported zero errors with 215 existing warnings. Actual Firestore SDK validation reproduces the original undefined-field failure and accepts repaired payloads; SDK leaf-mask tests verify preservation of omitted timestamp/measurement fields. The new fast-pan/Return-to-Live test reproduces the previous race before the fix. Private credential payloads were absent from browser JavaScript.

The three repaired Functions and Hosting were deployed to the established production project. A four-day recovery added 230 gauge readings and 593 NOAA readings, through 8:06 AM and 8:12 AM EDT respectively on October 14. Every pre-recovery observation key was retained. Recovered gauge gaps were at most 30 minutes and 2 seconds; NOAA gaps were six minutes. Both the scheduled and manually requested normal sync completed without the previous write failures; NOAA subsequently advanced to 8:18 AM. Live mobile verification at 390px showed a measured surge value and trend, identical chart domains, no page overflow, and hourly weather/comment controls outside the plot.

Production verification also found the dashboard withholding an available cached numerical outlook while relying on its Firestore SDK read. The existing `/api/outlook` cache is now the first read in both production and development, with the original schema/location/freshness checks, read deadline, retry behavior and Firestore fallback retained. Opening the dashboard still cannot run inference or Gemini. Five production-mode regressions failed before this change and pass afterward.

After the frontend release, the live dashboard selected **Extended outlook** and displayed the calculated summary updated at 8:31 AM EDT, alongside the recovered measured surge value and decreasing trend. At 390px and 1280px viewport widths, both chart domains matched and document width stayed within the viewport. Temporary viewport overrides were reset after verification.
